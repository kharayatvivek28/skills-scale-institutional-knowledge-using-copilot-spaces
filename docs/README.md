# OctoAcme Project Management Documentation

Welcome to the OctoAcme Project Management Docs—your guide to how we plan, execute, and deliver projects.

## Quick Overview

OctoAcme follows an iterative, customer-first project management approach built on clear ownership, data-driven decisions, and psychological safety. Our processes are designed to deliver customer value through small, testable increments while maintaining alignment across stakeholders and reducing single-person dependency risk.

**Key Principles:**
- Customer-first: prioritize customer value and usability
- Iterative delivery: deliver small, testable increments
- Clear ownership: each project has a named Project Manager and Product Lead
- Data-informed decisions: measure impact and iterate based on evidence
- Psychological safety: encourage feedback and learning

## Project Lifecycle

OctoAcme projects follow a structured five-phase lifecycle:

1. **Initiation**: Validate business need, align stakeholders, define high-level goals, and create a Project One-pager
2. **Planning**: Break work into shippable increments, identify dependencies and risks, build a prioritized backlog, and define Definition of Done
3. **Execution**: Build, test, review, iterate with regular standups, demos, and quality assurance
4. **Release**: Deploy to production with documented rollback plans, verification steps, and stakeholder communication
5. **Close & Retrospective**: Capture learnings, track action items, and drive continuous improvement

## Core Roles

- **Project Manager (PM)**: Coordinates delivery, manages schedules, risks, and communications
- **Product Manager (PdM)**: Defines outcomes, prioritizes the backlog, and measures success
- **Developers**: Implement features, collaborate on design and testability
- **QA/Testing**: Validate quality and acceptance criteria
- **Stakeholders**: Provide inputs and approvals

For detailed role descriptions and personas, see [Roles & Personas](octoacme-roles-and-personas.md).

## Key Artifacts

Across the project lifecycle, we create and maintain these key artifacts:

- **Project Charter / One-pager** — Problem, goal, success metrics, stakeholders, timeline
- **Roadmap and Release Plan** — High-level roadmap and milestone map
- **Sprint/Iteration Backlog** — Prioritized, estimated items with acceptance criteria
- **Definition of Done (DoD)** — Quality standards before considering work complete
- **Risk Register** — Identified risks with impact, likelihood, mitigations, and status
- **Project Board** — Columns: Backlog, Ready, In Progress, In Review, QA, Done
- **Retrospective Notes** — Learnings and action items for continuous improvement

## Communication Cadence

- **Daily standups** (15 min) — Progress, blockers, dependencies
- **Weekly PM + PdM sync** — Alignment on priorities and risks
- **Twice-weekly delivery team standups** — Status and blocker resolution
- **Weekly stakeholder updates** — Status, risks, decisions needed
- **Monthly stakeholder briefings** — Roadmap and milestone progress
- **Ad-hoc escalations** — For blockers and critical issues
